# Dashboard

The Mailquilt dashboard: a static single-page app built with TanStack Start in SPA mode, Kumo on Tailwind v4, and TanStack Query. It has no server of its own. It talks only to the API, through the typed client generated from `@repo/contract` (`src/api.ts`).

## Develop

```bash
pnpm --filter server dev     # the API on http://localhost:3000
pnpm --filter dashboard dev  # the dashboard on http://localhost:3001
```

`vite dev` forwards `/api/*` and `/health` to the API on `http://localhost:3000` (`server.proxy` in `vite.config.ts`). The port is fixed: if 3001 is taken, `vite dev` stops instead of picking another.

## Design

The bar, the process, the brand rules and the review checklist are in [`docs/agents/design.md`](../../docs/agents/design.md); the full logo kit is in [`docs/brand/`](../../docs/brand/). This section covers how the dashboard puts them into practice.

- **Theme:** `src/styles.css` sets Kumo's colour tokens for light and dark (`data-theme="mailquilt"` on `<html>`), plus the `text-display*` type sizes and the quilt radii. The frame has its own tokens (`--mq-frame-*`), the same in both modes because the frame is ink in both, and its subtree redeclares Kumo's tokens dark, so Kumo parts inside it draw as in dark mode. `--mq-scrim` is the dark wash under dialogs and sheets, and `--mq-warning-text` makes Kumo's light warning banner readable (5.9:1). Use those tokens, not one-off values. Two things to know before changing it:
  - Kumo declares its tokens on `:root` outside any cascade layer, so overrides of them must be unlayered too. Inside `@layer` they lose.
  - Kumo's primary button brings its own gradient and text colour. `styles.css` replaces them, and adds a visible focus outline to every Kumo button, in `@layer base` with `!important`.
- **Signed-out pages** (`src/layout/auth-layout.tsx`):
  - The form is centred in one light block, the same block signed-in pages sit in, set into a Flying Geese quilt (`src/brand/flying-geese-quilt.tsx`) with the frame's 8px seam; phones and tablets get a band of the quilt above it. A goose is the logo's envelope flap, and the orange column is a campaign going out. It lights up from the bottom once, unless reduced motion is on.
  - Fields and buttons are Kumo's default size, and sign-in and setup errors are Kumo banners with a warning icon.
  - The label sewn onto the quilt states the cost in plain numbers.
- **Signed-in pages** (`src/layout/app-shell.tsx`): the page is one light block set into the ink frame with the logo's 8px seam, on Kumo's `Sidebar` in its `inset` variant. The frame holds the logo, the Organization switcher, the navigation, faint geese at its foot and the account menu; it collapses to icons on desktop. Navigation items are the logo's blocks: a built page is a block with its count once that has loaded (none until then, when it couldn't be loaded at all, or when it's none; like the page, it keeps its last count if a later refresh fails), the current page is lifted off its dashed slot, and an unbuilt page is only the slot with Kumo's "Soon" badge. Every link shows a light focus outline, the current one included. Below 1024px the frame becomes a bar at the top, and the navigation opens full screen as Kumo's sidebar sheet, with 44px rows and a 44px close button where the menu button was. Going to a page or switching Organization closes it, and focus moves to the page; while it's open, the page behind it can't be reached. Pages own their own layout under `src/routes/_app/`.
- **Organizations** (`src/organizations/`): `useOrganizations()` gives the signed-in person's Organizations and the one this tab works in; pass `active.id` to every call for that Organization's data. The choice is remembered per tab, so two tabs can work in two Organizations ([ADR 0007](../../docs/adr/0007-tenant-endpoints-name-the-organization-in-the-path.md)). The switcher sits at the top of the sidebar; the home page's first step names the first Organization.
- **Organization patches** (`src/organizations/organization-patch.tsx`): each Organization is drawn as a 2×2 patch of the logo's ink and greys, arranged by its ID, so it keeps its patch when renamed. The logo's dashed slot always means a piece that isn't there yet (the next step, "New organization"), never a divider.
- **Page area:** every signed-in page's content sits in `PageFrame` (`src/layout/page-frame.tsx`), which `TablePage` and the form pages share, so they line up. It sets one gutter for the page (`--gutter`), which edge-to-edge tables and rows line up with. Tables (Contacts, Lists) use the page's full width, up to 96rem. A page that reads as one column (Providers, Instance settings, and connecting or editing an SMTP server) is capped at the form width (`--mq-form-width`, 60rem) and centred in the block (`mq-capped`), never left-aligned with an empty gap on the right; its header, dividers and states stop at the column, not the block's edge. Its header is `PageHeader` (`src/layout/page-header.tsx`): a two-tone display title like the wordmark, with `titleDetail` (such as a count) in quilt grey, one sentence, and the page's actions.
- **Dialogs** with one action use `ActionDialog` (`src/layout/action-dialog.tsx`). One that confirms something that can't be undone passes `destructive`, which draws its action in the danger colour and makes it Kumo's `alertdialog`, which a click outside doesn't close. On desktop it is Kumo's `Dialog`, centred, over the dark scrim, with Cancel beside the action at the bottom right. On phones it is a sheet from the bottom edge, rounded at the top, with the action above an outlined Cancel in that Tab order, built on Base UI's Drawer, because Kumo's `Dialog` stays a floating card on phones. While the action runs, nothing closes it and keyboard focus stays inside it. A form inside it is submitted by the action through the form's `id`. Open it through `useDialog`, and give it the hook's `key` and `handleExited`: the key moves on once a close has finished, so each opening starts fresh and the dialog animates both in and out. Never key a dialog yourself to reset it: a key shared by two dialogs left a closed one on the page, invisible and catching clicks. A dialog that opens by itself, such as Send test after a connect, passes `useDialog(true)`, which opens it just after it mounts, with its entrance.
- **Toasts** confirm something done that leaves you on the page, through `useConfirmationToast()` (`src/layout/toast.tsx`): Kumo's toast system, drawn with the logo's block settling onto its dashed slot, a strong title and at most one quiet line, with no close button.
- **Empty, didn't load and loading** are one pattern on every page (`src/layout/empty-state.tsx`): `EmptyState` (Kumo's `Empty` without its box, with the quilt picture and the actions to fill it), and `LoadFailed` (a dashed slot and Try again, which keeps keyboard focus while it retries). Loaders are the patch whose blocks fill in turn (`PatchLoader`), shown only after 300ms, so a quick answer never flashes it.
- **Forms** use TanStack Form and check their values with the schemas in `@repo/domain` (`Schema.toStandardSchemaV1`), the same ones the API uses, so a rule is written once. Each form sets `noValidate` and submits through `submitForm` (`src/forms/submit-form.ts`), which moves focus to the first field with an error. Every text field is a `FormField` (`src/forms/form-field.tsx`): Kumo's label, input and error, with the error tied to the input and announced again on every submit.
- **Fields on phones and touch screens** use 16px text (`max-sm:text-lg pointer-coarse:text-lg`, applied by `FormField`), because Safari on iPhone and iPad zooms the page into any field smaller than that, including in landscape, where the desktop layout shows.
- **Tables** (`src/audience/data-table.tsx`): headless TanStack Table (`@tanstack/react-table` 9) drawn with Kumo's `Table`, edge to edge on the page: a quiet header in subtle text over one hairline (not Kumo's elevated header fill), 48px hairline rows, selected rows tinted, and the first and last columns on the page's gutter. Columns are defined with TanStack's column helper, so later columns (custom fields, sorting, column visibility) are features to register, not a rewrite. A column's layout classes go in `columnClassNames` by its id; how a value looks belongs in its cell. On phones each row restacks into two lines instead of scrolling sideways, its columns placed by `areas` (the checkbox, the main line, the second line, beside the main line, or not shown); the rows keep explicit `row` and `cell` roles, because `display: grid` drops table semantics in Safari.
- **Table pages** (`src/layout/table-page.tsx`, `src/layout/table-region.tsx`): the page header, then the filters (`Toolbar`), then the table in a `TableRegion`, edge to edge with no card, with the pager below it. An empty or didn't-load state takes the rows' place under the same line; while the page first loads, the whole page area waits (`PageAreaLoading`). While the next page or filter loads, the last rows stay, dimmed, under a moving line (`busy`), so the table never empties and refills. The page's header action and count appear only once its data has loaded, and an empty state that offers the same action hides the header's.
- **Selected rows** get `SelectionBar` (`src/layout/table-region.tsx`): an ink bar floating at the foot of the page ("3 selected / Add to list / Clear"), so the filters and the rows never move when a row is ticked. It rises in, drops away when cleared, and inverts in dark mode. While it shows, toasts sit above it and Tab never lands under it.
- **Filters and pages live in the URL** through TanStack Router's search params, decoded with an Effect schema that drops any part it can't read (`src/audience/contact-search.ts`), so a reload, the back button or a shared link shows the same rows. Paging is Previous and Next over the API's cursors (ADR 0008), with the range and total beside them; Kumo's `Pagination` isn't used, because it counts pages by number and its simple mode shows unlabelled arrows.
- **Subscription status** (`src/audience/subscription-status.tsx`) is drawn with the logo's blocks and always written beside: ink is subscribed, the dashed slot is pending, pale is unsubscribed. The slot is an SVG dash, because at 12px a CSS dashed border draws as a solid outline. Lists shows each List's make-up as a bar of the same blocks, every bar drawn to the biggest List's scale.
- **Checkboxes and radios:** `styles.css` rings Kumo's unchecked ones in `--mq-patch-grey`, because Kumo's hairline ring is under the 3:1 contrast a control's boundary needs.
- **Loading:** a screen never draws a guess and changes it a moment later. Signed-in pages wait on `PageLoading` (`src/layout/page-states.tsx`) until the session and the Organizations list have loaded, and `PageLoadFailed` offers Try again when either can't be loaded. Every whole-page wait, and the page's own background before the app starts, is drawn on the frame's ink, because every page it leads to is ink around a light block, so a first load never flashes white. A page that loads its own data waits on `PageAreaLoading` in the page area, beside the sidebar, and draws once.
- **Who sees what:** `SignedInOnly` and `SignedOutOnly` (`src/layout/session-gates.tsx`) send people to the right side of the app. `useAccount()` gives signed-in pages the account without asking for the session again.
- **First-run setup** (`src/instance/`): every signed-out page waits on the install's status (`SetupGate`, around `_auth`) and sends a fresh install to `/setup`, which shares `NewAccountForm` with sign-up. Setup signs the new instance admin in and opens Instance settings with a note saying what's next. Sign-up shows "Sign-up is closed", and sign-in leaves out "Create an account", while the install is invite-only.
- **Instance settings** (`/instance`, in the account menu for the instance admin only): who can sign up, and the server account emails go out through, each a `SettingsSection` with its own save button. The server form is the Provider Connection form (`ConnectionForm`) without a name or Cancel, drawn as fields only inside its section (`nested`), with encryption as a segmented control, so both forms keep one set of rules. A server set by `SYSTEM_MAILER_*` environment variables shows as a sunk, read-only card. A save confirms with a toast, as every action that leaves you on the page does.
- **Verification links:** sending one always goes through `useSendVerificationLink` (`src/auth/send-verification-link.ts`), with one action name, "Send a new link".
- **Progress:** steps are marked with `StepBlock` (`src/brand/quilt-block.tsx`), drawn in the logo's language: an ink block with a check is done, the orange block lifted off its dashed slot is next, a bare dashed slot is a next step that isn't built yet, and a grey block is still to come. The next step's block lifts off its slot once as Home opens (`mq-lift`), the dashboard's one lift; with reduced motion it is already lifted.
- **Home** (`src/home/setup-steps.tsx`): the five steps in one open column with no card, joined by a seam that is solid below a done step and dashed for what's to come. Done steps shrink to a line saying what was done, the next step is set in the display face with its one action, and later steps say what to gather. While the next step isn't built, it says so and points to Contacts and Lists instead of offering an action.
- **Providers** (`src/providers/`): the page is one capped, centred column. Each Provider Connection is an open row in it, with hairlines between rows and no card: the ink block, its name and when it was connected on the left, Send test and a ⋯ menu (Edit, Delete) at the row's right edge, and who it sends as, its server and its security in three short columns underneath, lined up with the name. The header, the dividers and the note about direct connections share the column's width. On phones the details stack and Send test goes full width. Hosts and addresses wrap only after "@" or a dot (`Breakable`, `src/layout/breakable.tsx`). Send test opens a dialog (`ActionDialog`; a sheet on phones), which also opens by itself right after a connect or save. A test's result sits in a quiet panel under the address: the toast's done block when the Provider accepted the email, the empty dashed slot when it didn't, with the server's own words only when a server replied. The result takes focus as it appears, and stays, dimmed, while the person sends again, so the dialog doesn't jump. Delete is a `destructive` `ActionDialog`, with the danger confirm. Connecting and editing are full pages under Providers (`PageHeader`'s `crumbs`), because the form is long. A mutation writes its result straight into the cached list before refetching, so the page navigated to next never draws the old list. Kumo's loading `Button` disables itself and drops keyboard focus, so a button on a page that can be pressed again (Connect, Save changes) changes its label instead.
- **Settings and long forms** (`src/layout/settings-section.tsx`): each part is a `SettingsSection`, what it's for on the left and its fields on the right, one column below 1024px. A long form ends in the sticky `mq-form-foot` bar across the page block's full width, with Cancel, the submit button and, after a submit with errors, how many fields are left to fix. The form pages' `PageFrame` is `fullWidth`, so the bar reaches the block's edges on any window, while its contents stop at the centred sections' width (`--mq-form-width`): the error count lines up with their left edge and the buttons with the right edge of the section dividers. While it shows, the page's scroll padding keeps a focused field from landing under it.
- **The accent is used sparingly:** for brand moments (the logo, the quilt, the cost) and the single next step, never for ordinary actions. Primary actions are ink, because the accent sits next to error red.
- **Every screen has one job,** and its copy tells people what to do next. See `check-your-inbox` and the setup steps on the home page.

## Build

```bash
pnpm --filter dashboard build
```

The static files are written to `dist/client`, with the app shell as `index.html`. Both entry apps serve them next to the API: `apps/server` through `HttpStaticServer`, and `apps/api-worker` through Workers static assets (`assets` in `wrangler.jsonc`). A browser asking for a page that isn't a file or an API route gets `index.html`, so the router handles it in the browser. On Node that fallback applies only to paths without a file extension, so dashboard routes never end in one (`/campaigns/cmp_…`, not `/export.csv`). API routes live under `/api` ([ADR 0004](../../docs/adr/0004-api-routes-live-under-api.md)).
